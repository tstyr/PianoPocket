# 端末内でのAudio to MIDI

音声ファイルをAIで解析し、音符をMIDIに変換する機能を検討しています。現時点のAPKには変換画面やAIランタイムを含めていません。以下は実際のモデルを使った実現性調査です。

## 最初の候補

[Spotify Basic Pitch](https://github.com/spotify/basic-pitch)は単独の楽器の和音を扱い、公式にONNX・TensorFlow Liteモデルを提供しています。コードとモデルを含むリポジトリには[Apache-2.0](https://github.com/spotify/basic-pitch/blob/main/LICENSE)が適用されています。[ONNX Runtime](https://github.com/microsoft/onnxruntime)はMITライセンスです。有料API・アカウント・音声のサーバー送信を必要としない構成が可能です。

公式モデルをGitHubの固定コミットから追加取得し、サイズとSHA-256を検証します。取得後はオフラインで処理できます。APKにはランタイムを入れ、AIを使わない利用者はモデルを取得しない構成が考えられます。

調査した固定コミットは `fa5997af0a8210982619003269994a1be25eddf3`。

| モデル | ファイルサイズ | SHA-256 |
| --- | --- | --- |
| ONNX | 230,444 bytes | `2c3c1d144bfa61ad236e92e169c13535c880469a12a047d4e73451f2c059a0ec` |
| TensorFlow Lite | 204,448 bytes | `3db297d54af8e01c6e5618245c956b1d71b6a2b978cb2dedb527173186552676` |

小さいモデルで、ハイエンド端末だけに限定する必要はなさそうです。Android移植時にはARM64・16KiBページ対応のランタイム、入力音声のデコード・リサンプル、音符化、バックグラウンド処理、キャンセル、モデル削除を検証する必要があります。GPU/NPUによる高速化は未検証です。

## 実際に確認したこと

開発用PC（x86_64）でONNX Runtime 1.23.2のCPU実行を使用。入力は22,050Hz・モノラル、43,844 samples（約1.99秒）。出力は172フレームの音符・発音開始・音高輪郭です。

内蔵CC0ピアノのサンプルから作ったド・ミ・ソの単音と和音を入力し、単音はそれぞれの音程が最大、和音はド・ミ・ソが上位3音となることを確認しました。この短いPC検証では、1窓の推論が約0.02〜0.03秒、Pythonプロセス全体の最大RSSが約95MiBでした。初期化・音声ファイル全体のデコード・MIDI生成・Android処理時間はこの推論時間に含めません。

これは正解MIDIとの網羅的な精度評価ではありません。音符の開始・終了時刻、ベロシティ、ペダルを含む完成MIDIの精度はまだ検証していません。Galaxy S26で測定した値でもありません。

## ピアノ向けの追加候補

[High-resolution Piano Transcription](https://github.com/bytedance/piano_transcription)と[推論ツール](https://github.com/qiuqiangkong/piano_transcription_inference)は、ピアノの開始・終了・ベロシティ・ペダルを対象にしています。[公開チェックポイント](https://zenodo.org/records/4034264)は171,966,578 bytes（約164MiB）で、Zenodoのモデル利用条件はCC BY 4.0です。

こちらはAndroidでそのまま使える公式モデル形式ではなく、PyTorchからの変換、変換前後の出力一致、コードのライセンス本文、実機でのメモリ・処理時間の確認が必要です。Basic Pitchよりピアノ演奏の表現を再現できる候補ですが、アプリへの組み込みはまだ行っていません。

## Galaxy S26での進め方

12GBメモリの端末なら、短い窓に分けて処理する構成で検証する価値があります。端末の総メモリをすべてアプリに割り当てられるわけではありませんが、上記の小型モデルではメモリ量より入力音質・認識精度・発熱と処理速度の確認が中心になります。

最初はピアノ単体の音声ファイルを変換し、結果をMIDIライブラリに保存して編集画面で修正できる流れが適しています。単音・和音・速い連打・ペダル・長い残響・低い録音音量で、正解MIDIとの音程と時刻の誤差を測ります。複数楽器の完成曲から各パートを分離する処理は別の課題です。リアルタイム変換も、このファイル変換とは分けて検証します。
