# PianoPocket 0.4 performance UI

利用者提供のOpenThesia画面を参考に、横画面のロールと88鍵を中心に再構成。参考製品のコード・画像・ロゴを同梱せず、アイコンも独自のベクター描画です。外部依存関係の追加はありません。

## 操作

- 演奏画面は既定でsensor landscape。設定・ライブラリは向きを制限しません。「演奏画面は横向きを優先」をオフにすると自動回転へ切り替わり、設定を保存します。大画面やマルチウィンドウでOSが回転要求を無視する場合も縦配置へ対応します。
- 全画面表示。画面端からスワイプするとOSのバーを一時表示できます。Androidの戻る操作はパネルを閉じ、ライブラリ／設定から演奏へ戻ります。
- 上部に音源名・MIDI状態。鍵盤アイコンでMIDIライブラリ、三角で再生／一時停止、丸で録音／保存、四角で全音停止、フェーダーで音源パネル、︙で書き出し・設定・状態表示。ファイルを選ぶと時間とシークバーを表示。
- ロール下側の拡大アイコンで88鍵／2オクターブを切り替え、矢印でオクターブを移動。ペダルアイコンは押下状態を色で表示。鍵盤のマルチタッチと押す高さによるベロシティを維持。
- ドレミは既定オン。狭い88鍵では文字が小さいため、2オクターブへの拡大を使用できます。ラベルと表示時間は設定で変更。
- 各アイコンは48dpのタッチ領域、アクセシビリティ名と選択状態、長押し説明を持ちます。設定やメニュー内の項目は名称を表示します。

## 0.4.1の表示変更

ロールはkeyEnd（離鍵）で終わり、サステインによるend（発音終了）まで延ばしません。鍵盤の強調も押鍵だけを表示。音声と保存MIDIのペダル動作は維持し、SUSがペダル中に黄色になります。画面ペダル、ライブMIDIのCC64、ファイルのチャンネル別CC64を集計。ドレミを最大13sp／黒鍵11spへ拡大し、ファ／♯を縦に並べます。設定がオフなら表示しません。

## 0.4.2の文字と選択制限

ドレミは一行の横書き。不透明の白・太字・暗い縁取りで描画し、ファも他の白鍵と同じフォントサイズ・ベースラインです。ファ／♯等の長い名前は縦サイズを変えず、横方向だけ幅へ合わせます。最大16sp／黒鍵13spで、88鍵の実幅に応じて制限。ロールのvelocityによるalphaを削除し、不透明な色を使用。音声のvelocityは変えません。

MIDI追加のSAFピッカーはMIDI用MIMEのみを指定。DISPLAY_NAMEの拡張子がmid / midi（case-insensitive）以外の場合、streamを開く前に拒否します。AndroidのSAFは拡張子フィルター自体は提供しないため、providerの誤ったMIME表示にもインポート側の拡張子チェックで対応。汎用binary MIMEのMIDIはピッカーに表示されない可能性があります。

手動確認：異なる拡張子を選べない／追加できないこと、mid/midiを選べること、音源用のZIP選択を妨げないことを確認。ドレミon/off、88鍵と拡大表示でファのベースライン・サイズ、白文字と縁取り、トラック色が不透明であることを確認してください。

## 0.4.4の追従表示・横ズーム

ファイル再生のドレミはノートの元の矩形位置に配置し、画面下端へのclampを撤去。文字はノートと一緒に下へ動き、ロールの境界で自然にクリップされます。ノート開始後に文字を下端へ貼り付けません。鍵盤上の固定ドレミ、live入力の履歴表示とSUSは維持。

ロールの2指ピンチで横倍率1..6.5、横ドラッグでパン。ピンチ中心の音程を維持し、A0..C8の範囲で端を制限。ロール・鍵盤・hit testが同じKeyboardViewportを使います。拡大アイコンで88鍵（100%）へ戻り、再度押すとC4..B5の2オクターブへ。拡大中の矢印は倍率を維持して横へ1オクターブ分移動します。設定や縦表示時間は変更しません。

鍵盤上はマルチタッチの演奏専用。別の指でロールを動かしたとき、静止した鍵盤の指を新しい音程へ移す処理を避けます。ピンチを和音入力と誤認しないよう、ジェスチャーをロールに設置しています。ViewModel内の横倍率・位置は回転で保持し、アプリの再起動では88鍵へ戻ります。

実機確認：長いMIDIノートの文字が鍵盤へ落ち、残らないことを確認。ロール上でピンチイン／アウトし、ノート列と鍵盤が一致し、拡大後も正しい黒鍵・白鍵が鳴ることを確認。横移動・左右端・88鍵へ復帰・回転・ペダル保持・和音と録音も確認してください。実機未接続のため、この手順の成功を確認済みとは扱いません。

## 音源パネル

演奏画面の右側（縦向きではロール幅）に開き、鍵盤の位置を変えずに操作できます。音源名からも開けます。

- **ミキサー**：XMLのgroup/tagバインディングを持つ実コントロールを最大3本ずつ縦フェーダーに整理。HelsinkiはSM57 / OM1 / Room / Release / Pedal Noise。masterとOutputは独立した実際のパラメータとして表示。group bindingがない音源ではグループ別の通常スライダーを表示。
- **エフェクト**：Reverb Mix等のXMLコントロール、IR選択、XML順のチェーンとバイパス。連動するパラメータは同じ値の別スライダーを作らず参照名を表示。調整不可・音源準備中・書き出し中は対応する操作を無効化。
- **情報**：読み込み状態と未対応XMLの警告。︙の状態表示でも音源・MIDI両方の警告を確認可能。
- パネル側にもペダル操作。音源ライブラリから別音源を選択可能。スクロールしてすべてのコントロールへアクセスできます。

Windows VSTの読み込み・実行は未実装です。このパネルをVSTホストとして表示しません。0.3.1のIR音量補正・先読みリミッターを維持し、DSP処理方式は変更していません。

## 検証

Android ARM64ビルド、36 JVMテスト、Android Lint（エラー0）、既存native suiteを実行。実機／エミュレーターの画面表示・タッチ検証は未実施。スクリーンショットを実行結果として生成していません。

Galaxy S26での手動確認項目：

1. 旧版と同じ署名のAPKを上書きインストールし、既存音源・MIDIが残ることを確認。起動時の横画面と、横向き両方向の回転を確認。
2. 88鍵のロールと鍵盤の横位置が一致し、MIDIノートが鍵盤に到達した位置で発音することを確認。三角で再生／一時停止、シーク後の再開を確認。
3. 複数指で和音・黒鍵・スライドを演奏し、フェーダーパネルを開閉しても鍵盤が移動しないことを確認。ペダルを押して離す、全音停止、録音開始・停止後のペダル表示を確認。
4. 5マイクのフェーダーとMaster / Outputを調整し、IRを切り替え、Reverb Mixが1つだけ表示されることを確認。エフェクトのバイパスと残響、音割れ修正も聴感で再確認。
5. ︙から書き出し形式のダイアログを開き、横画面でスクロールして全形式・保存・取消へ到達できることを確認。WAVとMIDIの保存を確認。
6. ︙から設定を開き、ドレミオフ／オンと横画面優先オフ、縦画面回転を確認。アプリ再起動後も両設定が残ることを確認。
7. MIDIを選択済みの状態でライブラリを開き、回転しても演奏画面へ勝手に戻らないことを確認。USB / BLEの入力選択、ライブロールと録音を確認。
8. 画面端からOSバー表示、戻るジェスチャー、アイコンの長押し説明、TalkBackの操作名を確認。文字サイズ拡大時も各メニューをスクロールして操作できることを確認。
