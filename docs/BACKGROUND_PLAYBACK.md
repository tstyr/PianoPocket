# バックグラウンド演奏

## 使い方

設定 → 音の設定 → **アプリを閉じても演奏** をオンにします。画面オフ・ホーム画面・別のアプリを開いている間もMIDI再生、接続キーボードの演奏、録音を続けます。初期値はオフです。

通知には再生・一時停止・終了を表示します。終了は演奏を止め、録音中ならMIDIに保存し、背景演奏の設定をオフにします。次回は設定からオンにしてください。Android 13以降では初回の有効化時に通知権限を確認します。通知を拒否している場合、通知欄の操作は使えません。設定 → アプリについて → 通知の設定から変更できます。

通話等の音声割り込みで一時停止します。音声を再び使える状態になっても曲は自動再生しません。イヤホンを外した場合や他のアプリに音声を譲った場合は背景演奏を終了します。書き出し・プレビュー中は演奏を止め、アプリへ戻った後に復帰します。

OSの強制停止・プロセス終了・電池制限を超えた継続は保証しません。プロセス終了後の自動再開は行いません。再起動後は曲の設定と最後の保存位置を停止状態で復元します。

## 実装

- Media playback型のforeground service。Androidの音声フォーカスとMediaSession、通知を使用します。
- Activityとサービスが1つのViewModelStoreを共有し、MIDI入力ポート・ネイティブエンジンの重複生成を防ぎます。
- 最後の画面を閉じてもサービスがセッションを保持します。最後の所有者が終了したら、ポートと音声経路を閉じます。
- 背景では低頻度で再生位置を更新し、描画は停止します。必要な間だけ期限付きPARTIAL_WAKE_LOCKを更新します。
- 曲と音源の保存、完成した録音の保存は音声ワーカーで処理します。音声コールバックに通知処理や保存処理はありません。
- 起動時の設定復元でアプリが見えている間にサービスを開始します。BOOT_COMPLETEDからは起動しません。

## 検証

Androidビルド、JVM自動テスト、Lint、端末テストAPKのコンパイルを実施しています。開発環境にAndroid端末・エミュレーターはなく、サービスの実機試験は未実施です。

`BackgroundPlaybackDeviceTest` はActivity破棄後のサンプル時計の進行、同一セッションでの復帰、背景での入力と録音保存を検査します。接続したARM64端末で実行してください。

```sh
./gradlew connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=dev.pianopocket.BackgroundPlaybackDeviceTest
```

追加の確認：

1. 設定をオンにし、長いMIDIを再生。ホーム・画面オフでも音と再生位置が進み、復帰時に音が途切れないこと。
2. USB・Bluetooth MIDIキーボードで画面オフ中に和音・ペダルを演奏し、音と録音が維持されること。
3. 通知の一時停止・再生・終了が動き、終了後に残音・WakeLock・サービスが残らないこと。
4. 別アプリの音声再生、着信、イヤホン取り外しで停止し、突然再生しないこと。
5. 書き出しと演奏が同時に動かず、画面復帰時に音源を再準備できること。
6. 設定オフ、通知拒否、強制停止、タスク削除、省電力設定で挙動を確認すること。
