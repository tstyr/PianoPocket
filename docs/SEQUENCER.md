# MIDI / recording / piano roll / export — 0.3.0 alpha

## Implemented

SMF Type 0/1 import and lossless retention of MIDI events/metadata, global tempo-map integration, PPQN timing, running status, FIFO pairing of overlapping notes, per-channel sustain note intervals. Type 0 merges tracks; Type 1 preserves imported tracks. MIDI recordings are Type 1 in the app library and can be exported as either format. Files are copied into private storage and metadata is committed by rename. They survive process recreation; the last selected file loads on the next launch.

Compose uses a card library like the supplied reference screenshot. Falling Notes are aligned with the same geometry as the 88-key / two-octave keyboard. Track color, velocity opacity, pedal tail and currently pressed keys are shown. Katakana solfege appears on keys and sufficiently wide note rectangles; the setting disables both. MIDI playback draws future notes descending; live mode draws elapsed held/released notes as history, since live input has no known future. A segment-tree interval index finds visible file notes without scanning the entire song every frame.

Native playback holds a prepared vector of timed events and divides audio blocks at MIDI event boundaries. Timing uses the actual output sample rate. Pause, seek and EOF release only the file's internal channels (17–32), leaving live MIDI (0–15) and touch keyboard (16) independent. Seek restores controller/bend state on the background worker and resumes future notes; it does not recreate the middle of samples that started before the seek target. No runtime MIDI file parsing happens in the audio callback.

USB / BLE devices remain automatically connected, with a new per-port selection filter. The recorder captures only the selected input/channel plus screen keys if the screen/all input option is selected. Touch performance is saved on MIDI Channel 16. External Channel 16 and touch performance can be merged when all inputs are chosen. Recording and song playback are exclusive. Note-offs and pedal-up are appended when recording stops. A foreground exit or device removal stops and saves an active recording. Rotation keeps the ViewModel and its capture. Captured timestamps are converted to a fixed 120 BPM, 480 PPQN time base; note times have approximately 1ms tick resolution.

Audio export supports RIFF WAV PCM16 / PCM24 / IEEE Float32, 44.1 / 48 kHz stereo, with configurable 0–30-second tail (default 8). A separate native bank uses the current region mapping, microphone levels, master/output, polyphony, selected IR and effect parameters. Its fixed LRU cache decodes missing pages synchronously on the export worker, never on Oboe. WAV data is streamed to an app-private temporary file and then copied to the SAF destination. The cancel flag is checked while rendering and copying. Export failure removes the temporary file and attempts to delete the incomplete SAF document.

MIDI export contains MIDI data, not samples or rendered effects. Original XML/audio files and user MIDI files are not redistributed. PocketStudy.mid is an original scale/chord fixture, generated by tools/make_midi_fixture.py, with 19 notes, two tempos, pedal and a final rest.

## Limits

- 16 MiB SMF, 200,000 events, 256 tracks, two-hour duration, 256 library entries. Type 2 and SMPTE division are rejected. PPQN Type 0/1 are supported.
- Program Change, pressure, SysEx and unsupported CC remain in saved/exported MIDI, but have no synthesis effect; import warnings explain this. MIDI drums use the selected sampler instrument. No GM multitimbral switching, MIDI editing, track mute, learning mode or MIDI 2.0 UMP.
- Real-time MIDI input is applied in the next audio block; the receiver timestamp is used for recording, not future audio scheduling. UI is refreshed at roughly 30Hz. End-to-end input/display/audio latency is not measured here.
- Each callback consumes at most 2048 live and 2048 file events. Excess file event density stops playback with a warning; offline export fails instead of silently dropping events.
- Recording does not capture sound-control automation or microphone/effect slider movements. No overdub. Background recording service is not implemented.
- Export uses additional sample heads/cache/DSP memory while the live bank exists, plus temporary disk space. The 32–512 MiB sample budget is per bank, not a total process-memory cap. The selected tail length can truncate a longer release/delay/reverb; select a larger length when needed. MP3/AAC/FLAC export is not implemented.

## Galaxy S26 manual verification

1. Install the 0.3 APK over 0.2 (same debug signing key). Existing imported instruments should remain. Start with Pocket Tone; verify the 88-key/two-octave switch, multi-touch and pedal.
2. Import PocketStudy.mid in MIDI. It should show 120 BPM, 19 notes, duration 0:05; playback uses a tempo change after two seconds. Confirm falling notes line up with the active keyboard and pedal-tail coloring.
3. In Settings, disable/enable Katakana labels and roll view, and vary the time window. Rotate during playback/recording; ensure the controls remain accessible.
4. Connect USB MIDI. Select the device's output port under MIDI input, choose a channel, press chords and CC64, record for 10 seconds and save. Confirm the new library entry replays the same notes, velocity, duration and pedal. Repeat with BLE MIDI if supported. Disconnect during recording; verify it saves and clears held keys.
5. Select the imported Helsinki XF preset, set different microphone/reverb values, and export Type 0, Type 1, WAV16, WAV24 and Float32 with a sufficient tail. Open each exported file in a DAW/player. Compare MIDI notes/tempo, verify audio reflects microphone/effect controls and contains release/reverb tail.
6. Cancel a long WAV render and a large destination copy; inspect for incomplete files. Try low-storage conditions, invalid/truncated MIDI, density/size limits and app backgrounding. Confirm warnings and continued native instrument operation.
7. Record device/output route, sample rate/buffer, XRun count, DSP load, PSS, touch-to-sound and USB-to-sound latency; host tests do not substitute for these measurements.
