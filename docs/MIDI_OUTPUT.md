# 転調とMIDI出力

## MIDIを転調する

演奏画面の「その他 → 転調」で、半音ずつ±24半音まで変更できます。1オクターブ移動と「元に戻す」もあります。

再生音、ロール、再生中の鍵盤表示、練習の待機キー、MIDI・音声・動画の書き出しに反映します。元のライブラリファイルは変更しません。別の曲を選ぶと転調は0に戻ります。

ドラムの10チャンネル、画面鍵盤、リアルタイム入力は転調しません。ノートオフ・ポリプレッシャー・調号をノートと一緒に移動し、テンポと演奏時間を維持します。0〜127のMIDI音域を外れるノートはオン／オフの両方を除外し、警告を表示します。画面上の音域や実際に鳴る範囲は、鍵盤の表示範囲・音源のマッピングにも従います。

## 外部MIDI機器に送る

1. USB MIDI機器を接続します。Bluetooth MIDIは「設定 → MIDI入出力」で検索・接続します。
2. 「その他 → MIDI出力」、または「設定 → MIDI入出力」を開きます。
3. 「MIDI出力」で送信先のポートを選びます。
4. MIDIを再生するか、画面鍵盤を弾きます。

受信ポートを持つ機器だけが送信先に表示されます。MIDIファイルは元のチャンネルで送信します。画面鍵盤は初期値が16チャンネルで、設定から変更できます。ファイル再生と画面鍵盤を併用するときは、チャンネルを分けるとそれぞれの停止・ペダル操作を分離できます。同じチャンネルでは外部機器側で1つの演奏として扱われます。

入力キーボードも送りたい場合は「入力キーボードも出力する」をオンにします。初期値はオフです。出力先の機器から戻ってきた入力は再送しません。「鳴らす音」で内蔵音源・外部MIDI・両方を選べます。外部MIDIだけにしても音源の保存済み音量やMIDIのベロシティは変わりません。

Note On / Off、Velocity、CC（CC64 / CC7 / CC11を含む）、Pitch Bend、Program Change、ポリプレッシャー、チャンネルプレッシャーを送信します。SysEx・MIDI Clock・MIDI 2.0 UMPは送信しません。エフェクト音声やサンプルデータはMIDIには含みません。

MIDI出力はアプリ起動時にオフです。出力先変更、入力転送・チャンネル設定の変更では残音を止めます。一時停止・シーク・リピート・曲の切り替えはファイルで使うチャンネルを停止し、必要に応じてペダル・バンク・音色・コントローラーを復元します。アプリが背景に移るとき、書き出し・プレビュー中、接続解除時も残音を止めます。

## 処理と検証

C++の再生エンジンが、発音と同じサンプル位置で送信イベントを作ります。事前確保した4096枠のSPSCキューで渡し、Android MIDI APIの送信・flush・ポート操作は専用のMIDI I/Oスレッドで行います。UIのFPSで送信をスケジュールしません。

イベント時刻はmonotonic clockと出力バッファ・リミッターの長さから推定します。Android MIDIへ未来のタイムスタンプを渡しますが、実際の送信遅延・内蔵音声との同期はUSB／Bluetooth機器と音声経路に依存します。実機での送信・同期・遅延は未測定です。

キューがあふれるとMIDI出力だけを停止し、内蔵音源の再生は維持します。接続先を選び直すと再開できます。世代番号で旧接続先向けのイベントを除外し、シーク時には最後のコントローラー状態のみを追跡するため、過去の大量イベントを送信しません。

- JVM：転調、ドラム除外、音域端、調号、MIDI Type 0/1の書き出し、練習キー・ロール、送信バイト列・長さ・時刻、停止・ペダル解除を確認。
- C++：バッファ内のノート時刻、ノートオフ、転送のオン／オフ、接続先変更、エコー抑制、シークのバンク／Program Change、リピートのペダル復元、キュー超過時の内蔵再生継続、音声処理内の動的確保0を確認。
- Androidビルド・Lint、ネイティブテスト、ASan / UBSanを実行。USB／Bluetooth機器での実機試験は未実施です。

## 音の切り替え

「その他 → 鳴らす音」または設定から、内蔵音源・外部MIDI・両方を選びます。外部MIDIだけのときも保存した音量は変更しません。出力先の切断時は内蔵音源が鳴る状態に戻ります。出力先とモードは起動時にリセットします。接続先を選ぶと両方のモードになります。

内蔵音源への切り替え時は外部機器の残音を止めます。外部出力を有効にした時点で既に押されているノートは再送せず、以後のイベントを送ります。切り替え中も再生位置は進みます。書き出しにはこの出力モードを適用せず、音源に保存した音量を使います。
