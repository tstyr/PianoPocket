# アプリの更新

「設定 → アプリについて → 更新を確認」から最新版を確認できます。新しい版がある場合、変更点を見て「APKをダウンロード」を押します。取得後は「インストール」でAndroidのインストール画面を開きます。

初回はAndroidの「この提供元のアプリを許可」をオンにする画面が出ます。戻って「インストール」を押してください。更新でアプリのデータは引き継がれます。インストール前に録音や書き出しを完了してください。

更新の確認と取得は手動です。起動時の自動通信や自動インストールはしません。音源の演奏は引き続きオフラインで使えます。GitHubに置かれた静的ファイルから取得するため、アカウント・APIキー・独自サーバーは不要です。

APKの取得は通知から進捗・キャンセルを確認でき、画面を閉じても継続します。通知を許可していなくてもアプリ内から使えます。通信が途切れた場合は再試行で続きから取得できます。プロセスが終了すると取得はいったん停止します。取得済みの情報とAPKは再起動後も利用できます。

## 検証と上限

- 更新先は `tstyr/PianoPocket` の `release-artifacts` ブランチのHTTPS URLに限定。
- 更新情報は16KiB、APKは128MiBまで。
- APKのサイズ・SHA-256、アプリID、バージョン、最小Android版を照合。
- Androidから取得したAPKの署名証明書を、現在インストール済みのアプリと照合。違う署名は受け付けません。
- Androidのインストール画面を開く直前にも再検証します。
- バージョンコードが新しいARM64用の版だけを更新として案内します。
- 取得完了後は以前の更新APKを削除。ファイル共有は更新フォルダーだけに限定。

署名鍵の変更・ローテーションは、この更新機能では扱いません。現在のデバッグ署名の試用版と同じ署名のAPKを使用します。

ホストの自動テストで取得・再開・サーバーによる再開始・ハッシュ不一致・過大サイズ・不正URL・キャンセルを確認。Android用テストには更新情報の解析と同一バージョン拒否の確認を含めていますが、実機未接続のため端末上では未実行です。実機では古い版からの更新、提供元の許可画面、通信中断、再起動、録音データの引き継ぎを確認してください。

## 公開する側

テスト済みAPKの署名とアラインメントを確認してから、`tools/update_manifest.py`で`latest.json`を生成します。APKと同じ配布ブランチにコミットし、公開後にマニフェストのAPKサイズ・SHA-256を再確認します。更新情報は最新のAPKを指します。

```sh
python3 tools/update_manifest.py --apk artifacts/PianoPocket-VERSION-arm64.apk \
  --notes release-summary.txt --output latest.json
```
